# 📊 نظام تحليل أداء السكتورات - AlwahaNet

نظام ذكي لمراقبة وتحليل أداء سكتورات الشبكة اللاسلكية باستخدام بيانات Zabbix.

## 💡 المهام الرئيسية
- حساب عدد الزبائن وسرعة الإنترنت لكل سكتور.
- تصنيف السكتورات إلى: جيد، ازدحام، ضعيف جدًا، متذبذب، يحتاج دعم، بلا بيانات.
- عرض واجهة رسومية عبر Flask و DataTables.
- حفظ الأداء اليومي في قاعدة بيانات `Sectors`.

## ⚙️ بيئة العمل
- Python 3
- Flask
- MySQL (MariaDB)
- Zabbix MySQL DB (version 6)

## 👨‍💼 مستخدمو النظام
- مدير قسم الأبراج.
- المدير العام.
- الفريق الفني لمراقبة الأداء.




📊 **ملخص مشروع مراقبة أداء السكاتر (Sectors Dashboard Project)**

## ✅ أهداف المشروع:

1. **تحليل الأداء اليومي** لسكتورات الوايرلس.
2. **إنشاء واجهة رسومية** تفاعلية لعرض الإحصائيات لكل سكتور.
3. **تخزين الأداء بشكل دوري** (يوميًا) في قاعدة بيانات محلية.
4. **تقييم تلقائي لحالة كل سكتور** بناءً على عدد الزبائن وسرعة التحميل.
5. **إعداد تقارير يومية وأسبوعية وشهرية** لدعم اتخاذ القرار الفني والإداري.

---

## 🏗️ مكونات المشروع:

1. **collect\_stats.py**

   * مسؤول عن استخراج الأداء اليومي من Zabbix (قاعدة بيانات zabbix\_db).
   * يجلب:

     * عدد الزبائن في الذروة.
     * متوسط وأقصى سرعة تحميل (بالميغابت).
     * عنوان IP لكل جهاز.
     * اسم السكتور والفرع.
   * يستخدم جدول `trends_uint` في Zabbix لقراءة البيانات خلال الذروة (20:00 إلى 00:00).
   * يتم تصنيف كل سكتور بناءً على معايير محددة، ثم تُخزن النتائج في قاعدة بيانات `Sectors`.

2. **app.py**

   * تطبيق Flask يعرض البيانات المخزنة في واجهة ويب.
   * يدعم الفلاتر حسب الفرع والحالة.
   * يعرض أحدث قراءة لكل سكتور لليوم.

3. **dashboard.html**

   * صفحة HTML تعرض الجداول باستخدام DataTables.
   * يدعم الفأرة التوضيحية لكل عمود (Tooltips).
   * تم تحسين التصميم باستخدام CSS وFont Cairo.

4. **قاعدة بيانات الأداء (Sectors):**

   * الجدول الرئيسي: `sector_stats`
   * الأعمدة:

     * `id` (رقم تسلسلي)
     * `branch` (الفرع)
     * `hostname` (اسم السكتور)
     * `ip` (عنوان الجهاز)
     * `max_clients` (أقصى عدد زبائن في الذروة)
     * `avg_mbps` (متوسط السرعة)
     * `max_mbps` (السرعة القصوى)
     * `load_ratio` (نسبة السحب = متوسط السرعة ÷ عدد الزبائن)
     * `peak_load_ratio` (أقصى سحب = السرعة القصوى ÷ عدد الزبائن)
     * `status` (حالة السكتور)
     * `last_updated` (تاريخ ووقت القراءة)

---

## 🎯 معايير التقييم التلقائي (في دالة `classify_sector`):

* إذا كان `max_clients` أقل من 10: → يحتاج دعم.
* إذا كان `max_clients` > 50 و `avg_mbps` < 8: → ازدحام.
* إذا كانت `max_mbps` < 4: → ضعيف جدًا.
* إذا كانت `avg_mbps` < 3 و `max_mbps` > 10: → متذبذب.
* إذا كانت `avg_mbps` ≥ 10: → جيد.
* إذا لا يوجد بيانات: → بلا بيانات.

> المخرجات يمكن أن تكون أكثر من حالة واحدة (مثلاً: "ازدحام / متذبذب").

## 📋 أنواع التقارير:

### 🔹 يومية (للمراقبة السريعة):

* قائمة أسوأ 10 سكتورات حسب الحالة.
* ملخص الأداء لكل فرع.
* سكتورات بدون بيانات.

### 🔸 أسبوعية:

* رسم بياني بعدد الزبائن لكل سكتور خلال الأسبوع.
* معدل التحميل الأسبوعي.
* سكتورات تكررت فيها حالات "متذبذب" أو "ضعيف جدًا".

### 🔷 شهرية (للإدارة):

* متوسط عدد الزبائن لكل فرع.
* تحليل أكثر السكتورات ازدحامًا.
* عدد المرات التي ظهرت فيها كل حالة (تكرار الحالة).
* تقرير مقارنة الأداء الحالي بالشهر السابق.
